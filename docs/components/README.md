## 每个组件必须说明什么

使用[组件文档模板](_template.md)，至少包含：

1. 组件介绍、适用场景及明确的范围限制。
2. Vue、React、Angular 各自实现状态和验证范围。
3. JS/类型与 CSS 导入、最小用法及常见组合。
4. 参数的名称、类型、必填性、默认值、行为和框架差异。
5. 事件、回调、output 的 payload、时序，以及外部赋值是否触发。
6. slot、render callback、内容投影或 TemplateRef；实例方法与 ref。
7. 原生属性落点、组件掌握的内部状态、无障碍命名与键盘。
8. 表单提交、禁用、校验、reset，以及框架 Forms 集成。
9. 主题、字体、字号、密度、局部覆盖与浮层 host。
10. SSR/水合、清理责任、已知限制和验收记录。

## 用法与状态标记

“已交付”只用于真实公开入口已经存在的组件。每个框架单独记录状态；SSR、表单、浏览器验证也各自记录，不由其他框架的结果推断。

已实现用法使用真实 import、公开类型和可验证的示例。尚未实现的框架使用“规划用法，当前不可用”标签，列出预期语义与特殊 API，不编造安装后即可运行的导入。尚未冻结的 selector、模板 directive 或导出名明确写待定。

后续实现 React/Angular 组件时，应同步更新对应章节和支持矩阵，补齐原生类型、浏览器、表单和 SSR 证据。不能只移除“规划”标签。

## 与代码同步

组件的同一个开发 Task 必须同时交付代码、示例、测试和对应 MD。参数、默认值、事件、样式入口或边界变化时，文档一起更新。没有组件 MD 的新组件不标记 Task 完成。

可执行示例放相应框架的消费宿主，从公开包名导入；文档用例与这些示例保持一致。规划示例不计实际编译或运行通过。验证摘要链接到 `docs/engineering/`，大体积日志和 trace 留在被忽略的 `.artifacts/`。

后续 Wiki 可以调整导航和排版，API 与行为依据仍以这些 MD 和公开类型、实际实现为准。

Task8 的最小表单、主题、SSR 和 layer 夹具只验证基础方案，不能据此把 Select/Combobox/Dialog 标为已实现；范围见 [Task8 验收](../engineering/task8-acceptance.md)。产品文档必须写明 value/open/query 各通道的所有权与拒绝回写结果，并将自动化、设计评审、人工读屏/IME 分栏记录。
